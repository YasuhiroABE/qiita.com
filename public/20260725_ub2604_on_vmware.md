# はじめに

Xubuntu 26.04とVMware Workstation Pro 26H1の組み合わせにしてから、Displayの制御が少し変わった印象です。

通常のGnome版 Ubuntu 26.04 Desktop版で試してみると、X11とWaylandの違いはあるものの、現象は似ているようです。

Xubuntu 24.04では問題なかった状態から26.04にアップグレードすると、ウィンドウのリサイズとモニター解像度の設定が自動では追従しなくなり、手動で選択できる解像度が高々XGA(1024x768)程度になりました。

概ねvmwgfxモジュールに起因する問題のようにみえますが、根本原因の追究は一旦あきらめて、対処方法を探すことにしたので顛末をメモしておきます。

# 結論

Xubuntu 26.04(Xfce)の環境では対処療法的に、次のようにしています。

* ``open-vm-tools-desktop``パッケージを **インストール(install)** する
* ``xserver-xorg-video-vmware``パッケージを **アンインストール(uninstall)** する

通常は``open-vm-tools``や``open-vm-tools-desktop``パッケージは自動的にインストールされると思いますが、Server版から``xubuntu-desktop``パッケージを導入するような運用をしていると``open-vm-tools-desktop``パッケージを導入する必要があるかもしれません。

# 遭遇した2つの現象

VMware Workstation Proのウィンドウサイズを変更しても、X11/Waylandがきちんと追従しない問題に遭遇しました。

下図のようにウィンドウの切り替えなどのタイミングで、正常に描画されずに画面右上に縮小されて表示されてしまったり、ブラックアウトしてしまって、いずれにしても正しく画面が描画されなくなっています。

# 対処法

パッケージについては冒頭に書きましたが、その環境下ではおよそ次のような手順で解決しています。

あらかじめ**Display**設定から希望する画面の解像度をマニュアルで選択した状態で、「フルスクリーンモード」を選択した、もしくは、VMware Workstationウィンドウの「最大化ボタン」を押下した状態から次のような操作をします。

1. 「自由に拡大縮小」、あるいは、「拡大縮小の縦横比率を維持」のいずれかを選択する (ツールバーのアイコンでも可能)
2. 最大化を解除し、VMware Workstation Pro のウィンドウをリサイズする
3. 再び「フルスクリーンモード」もしくは「最大化ボタン」を選択し、元の画面サイズに変更する

![20260727.102158.screenshot.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/78296/fbe338bc-0dc5-4703-8143-7f509072c630.png)

ほぼこの手順で正常な画面に戻っています。

# 問題の発生している環境

利用しているのは次のような環境です。

* ThinkPad T14 Gen2 (CPU: i7-1165G7, Memory: 48GB)
* VMware Workstation 26H1 for Windows (Windows 11 Pro 25H2)

T14はNVIDIA GeForce MX450を搭載していますが、通常は使用していません。

仮想マシンのディスプレイ設定では3Dのアクセラレーションは無効にしていますが、NVIDIAのdGPUカードを積んでいるLinuxマシンでは、有効化しても問題ないようなので、環境に合わせて設定すればいいようです。

## 仮想マシンの導入状況

確認した環境は次のような仮想マシンで、Wayland/X11の両方の環境で確認しています。

### Wayland仮想マシン

Ubuntu 26.04 Desktop版をVMware Workstationの自動インストール機能で準備したVMです。

* 標準構成のままインストールしたのでWaylandが動作している
* Xubuntu(X11)ではなくGnomeが動作する通常のUbuntu
* vmwgfxとの相性問題は別途対応する必要がある (モジュールの設定でoptions vmwgfx force_coherent=1, options vmwgfx restrict_dma_mask=1を有効にしています)

Waylandでは``xserver-xorg-video-vmware``パッケージをアンインストールする必要はありませんでした。

### X11仮想マシン

Ubuntu 26.04 Server版を通常メニューから新規インストールしたVMです。

* OpenSSH Serverのインストールを選択
* その他はデフォルトのまま、追加のパッケージ導入はなし
* 稼動後に、手動で``xubuntu-desktop``をインストール

Xubuntu 24.04から``do-release-upgrade -d``でアップグレードしたVMでも確認していますが、このケースとまとめて扱っています。

X11が動作している場合、高解像度を選択するために``xserver-xorg-video-vmware``パッケージをアンインストールする必要がありました。

# X11で高解像度が選択できない理由

``xserver-xorg-video-vmware`` には ``vmware_drv.so`` ドライバモジュールが含まれています。

Xubuntuの ``/var/log/Xorg.0.log`` ログファイルを確認すると、次のようなメッセージがあります。(Wayland環境下では、このログファイルは存在しません)

```text
[    21.919] (II) vmware(0): Driver was compiled without KMS- and 3D support.
[    21.919] (WW) vmware(0): Disabling 3D support.
[    21.919] (WW) vmware(0): Disabling Render Acceleration.
[    21.919] (WW) vmware(0): Disabling RandR12+ support.
...
[    22.346] (--) vmware(0): vram:  4194304
```

仮に3Dアクセラレーションを有効化しても、このメッセージ自体は変化しません。

約4MBのVRAMしか有効化されていないことが原因です。

これを解決するために、``xserver-xorg-video-vmware``パッケージをアンインストールすることで、問題になった ``vmware_drv.so`` ドライバモジュールを読み込まないようにすることで対応します。

```bash:
$ sudo apt remove xserver-xorg-video-vmware
```

再起動して確認すると、無事に高解像度が選択できるようになっています。

このパッケージは``open-vm-tools-desktop``パッケージの関連パッケージとして導入されています。

``open-vm-tools-desktop``を導入しなければ問題は発生しませんが、導入しないと Copy & Paste のようなホストOSとの基本的なコミュニケーションが取れなくなってしまうため、個別にアンインストールしています。

WaylandはXサーバーではないことから、高解像度が選択できない原因となった``vmware_drv.so``自体がロードされないため、``xserver-xorg-video-vmware``パッケージの有無は関係ないことになります。

# まとめ

どちらの環境もホストOSからのウィンドウのリサイズといったイベントをうまく処理できていないというより、画面表示がミニサイズになってしまう点から、VMware Workstation側の描画機能や画面リサイズなどのイベント通知機能に問題がありそうです。

Ubuntuに限らずLinuxデスクトップの今後はWaylandに統合されていくと思われますが、Xサーバーは開発された当時としては分散環境指向で、非常に見通しの良いソフトウェアでした。

WindowsNTの描画サーバーもXサーバーも、GPUへの依存度が高くなっていく上でメモリアクセスの最適化や、効率的な描画APIへのニーズによって、様々な変更に見舞われてきた印象があります。

何よりも複数dGPUを備えたデスクトップ環境というのは30年以上前には、想像できなかったと思います。

X11が廃れていくのは寂しいですが、生成AIなどローカルGPU処理がより重要になっていく中で、Waylandへの移行が成功して安定し、より高速なデスクトップ環境が得られることを願っています。
